Enter the project — describe the output; the P0 methodology does the decomposition

This wizard is prompt P0 (research & decompose) encoded as an interface: your desired result becomes L0, detected outcome-domains become L0.x, the proven FREECC engine (L1 → C1–C5 → 18 sub-issues, all gate-backed) is attached underneath, and every generated issue carries variables, roles, method→evidence links (E#), a spectral index (I#), a mechanical gate (G#) and the recommended prompt (P#). Truth rule enforced by the UI: an issue with an evidence gap cannot be marked resolved — it must go through P0 step 2 first.

Free provider roster — who can answer, and in which role

Ported from free-research-llm (MIT, commit d5ca596). Three roles, the same split as the router groups: deep (plan, architect, retries), fast (every implement and research step) and reviewer — which must be a different provider from the one that produced the answer, because the verifier is never the doer. A verified provider is one this machine actually got content back from; the rest are documented upstream but not exercised here.

A model cannot cite what was never fetched. Retrieval keys are what turn “I think” into “this page says”.

Two rules worth stealing

1 · Never hard-code a model id. Read the provider's /models list and pick the best match from an ordered preference list, so a renamed or retired model degrades to the next name instead of stopping the fleet. This repo's own shipped defaults failed exactly this way: gemini-3-pro never existed and qwen3-coder:free was withdrawn.
